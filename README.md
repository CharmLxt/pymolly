pymolly (или просто Молли) — это дружелюбный баг-репортер для Python. Библиотека перехватывает ошибки и объясняет их простым языком, подсказывая возможные причины и способы исправления. Вместо стандартного стектрейса на тридцать строк Молли выводит короткое понятное сообщение: что за ошибка, что она означает, из-за чего обычно возникает и как её исправить. Библиотека работает только через import, никаких консольных команд нет.



В составе четыре независимых модуля. Molly — базовый уровень: ловит исключение и объясняет его. Работает в четырёх режимах: как контекстный менеджер (with Molly():), как декоратор (@Molly.watch), вручную через try/except с Molly.catch(e) и через глобальный хук Molly.install\_global\_hook(), который заставляет все непойманные ошибки проходить через Молли. Для каждой ошибки Молли использует базу знаний из 25+ типов исключений, включая NameError, TypeError, ValueError, ModuleNotFoundError, FileNotFoundError, PermissionError, IndexError, KeyError, AttributeError, SyntaxError, IndentationError, ZeroDivisionError, RecursionError, MemoryError, ConnectionError, TimeoutError, NotImplementedError, StopIteration, RuntimeError, UnicodeDecodeError, UnicodeEncodeError, AssertionError и OSError. Для каждой ошибки база содержит описание, вероятные причины и конкретные подсказки.



mlMolly (Maniacal Molly) — более умная версия. Перед запуском функции она проверяет исходник через ast-парсер и ищет опечатки в именах переменных, функций, классов и импортов. Встроенная база из нескольких сотен типичных опечаток (lenght вместо length, improt вместо import, retrun вместо return, helpr вместо helper) плюс нечёткий поиск через difflib среди определённых в файле имён, ключевых слов и встроенных функций. Если mlMolly находит подозрительное имя, она печатает предупреждение с указанием строки и возможного правильного варианта. Точной гарантии она не даёт, но простые случаи ловит уверенно. Используется как декоратор @MLMolly.watch, как функция MLMolly.check\_file(path) или как MLMolly.check\_function(func).



MollyWaff (Molly with affection) — интерактивный автофикс. Когда происходит ошибка, MollyWaff анализирует её, определяет, можно ли автоматически починить, и предлагает пользователю интерактивное меню с вариантами. Для FileNotFoundError она предлагает создать отсутствующий файл или переименовать похожий файл. Для ModuleNotFoundError — установить модуль через pip или заменить имя модуля в файле. Для NameError — заменить похожее имя в файле. В любом случае есть опция «точечный фикс», где пользователь сам указывает номер строки, сколько символов удалить и на что заменить. После каждого успешного фикса MollyWaff пишет сообщение об успехе и случайную фразу поддержки. Если фикс не удался — сообщает об этом, предлагает альтернативу и подбадривает. Есть режим декоратора и контекстного менеджера.



GuMolly (Molly Guard) — журналирование, мягкая остановка и чекпоинты. Логирует каждую ошибку в папку \~/.pymolly/all\_logs с подпапками def\_logs (обычные ошибки) и crit\_logs (критические). Критическими считаются MemoryError, RecursionError, SystemError, KeyboardInterrupt, SystemExit, а также любая ошибка, которая повторилась три раза и больше за сессию. Журнал — это JSONL, по одной записи на ошибку, с timestamp, типом, сообщением, файлом, номером строки, флагом критичности, счётчиком повторов и полным traceback. При ошибке GuMolly может мягко остановить выполнение: ставит флаг, следующие вызовы через GuMolly.watch просто возвращают None без выполнения. После исправления пользователь вызывает GuMolly.resume() — и работа продолжается. Есть методы GuMolly.save\_checkpoint(state, path) и GuMolly.load\_checkpoint(path) для сохранения произвольного сериализуемого состояния, и метод GuMolly.run\_with\_checkpoint(task\_fn, state\_path, max\_iterations, show\_progress), который гоняет task\_fn в цикле с автоматическим чекпоинтом после каждой итерации — так прерывание на любой итерации позволяет возобновить работу с той же точки при следующем запуске. Журналы можно читать через GuMolly.get\_logs(date, level) и очищать через GuMolly.clear\_logs().



Все четыре модуля используют общий слой charm\_enhance, который мягко интегрируется с CharmPkk. Если CharmPkk установлен, Молли печатает сообщения через CharmPkk console: красивые рамки, цветной текст, прогресс-бары, спиннеры, интерактивные меню со стрелками. Если CharmPkk не установлен, всё работает на чистом print с ASCII-рамками и нумерованными меню. Зависимостей нет, только стандартная библиотека Python. Установка: pip install pymolly. Опционально: pip install "pymolly\[charm]" для красочного интерфейса.



Использование простое. Базовая Molly: with Molly(): risky\_code(). mlMolly как декоратор: @MLMolly.watch над функцией. MollyWaff вместо Molly там, где нужен интерактивный фикс: @MollyWaff.watch. GuMolly для журналирования: @GuMolly.watch или GuMolly.install() для глобального хука. Все модули совместимы между собой — можно использовать MollyWaff для фикса и GuMolly для журналирования одновременно, они не конфликтуют.
